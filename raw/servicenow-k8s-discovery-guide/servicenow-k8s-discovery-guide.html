Guida all'integrazione e al popolamento CMDB per ServiceNow

1. Lato Kubernetes (Cluster)

  • MID Server (Pod o Docker): Il connettore Java di ServiceNow. Può girare direttamente come Pod K8s nella tua infrastruttura.
  • ServiceAccount RBAC: Utente di servizio Kubernetes (es. servicenow-discovery-sa).
  • ClusterRole & Binding: Permessi di sola lettura (get, list, watch) su API K8s.
  • ACC-K8s (Opzionale): Agent Client Collector per eventi K8s in tempo reale via Helm.
☁️

2. Lato ServiceNow (PDI)

  • ITOM Visibility / Discovery Plugin: Modulo com.snc.discovery attivato sulla PDI.
  • Patterns Package: App Store Discovery and Service Mapping Patterns.
  • CMDB CI Class Models: Modello dati CMDB esteso per Kubernetes (Tabelle K8s).
  • Kubernetes Credentials: Record credenziale con Bearer Token K8s.
🔄

3. Flusso di Comunicazione

La comunicazione tra la tua rete locale e ServiceNow avviene in sicurezza:

  • Outbound HTTPS (443): Il MID Server interroga ServiceNow tramite web-socket/polling. Nessuna porta aperta in ingresso!
  • In-Cluster REST API: Il MID Server interroga l'API Server di K8s via TLS (6443) usando il Bearer Token.
Istruzioni Pratiche di Configurazione (Step-by-Step)
1

Creazione del ServiceAccount e Ruoli RBAC in Kubernetes

Esegui questo manifest YAML sul tuo cluster Kubernetes per creare l'accesso di sola lettura a ServiceNow:

apiVersion: v1
kind: ServiceAccount
metadata:
  name: servicenow-discovery-sa
  namespace: default
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: servicenow-discovery-role
rules:
- apiGroups: ["", "apps", "batch", "networking.k8s.io"]
  resources: ["nodes", "namespaces", "pods", "services", "deployments", "statefulsets", "daemonsets", "replicasets", "ingresses", "configmaps"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: servicenow-discovery-binding
subjects:
- kind: ServiceAccount
  name: servicenow-discovery-sa
  namespace: default
roleRef:
  kind: ClusterRole
  name: servicenow-discovery-role
  apiGroup: rbac.authorization.k8s.io
2

Generazione del Bearer Token

Genera il Bearer Token da inserire in ServiceNow:

kubectl create token servicenow-discovery-sa --duration=8760h -n default
3

Deploy del MID Server su Kubernetes (Opzione Container)

Puoi fare il deploy del MID Server direttamente su Kubernetes inserendo la chiave e l'URL dell'istanza:

apiVersion: apps/v1
kind: Deployment
metadata:
  name: servicenow-mid-server
  namespace: default
spec:
  replicas: 1
  selector:
    matchLabels:
      app: mid-server
  template:
    metadata:
      labels:
        app: mid-server
    spec:
      containers:
      - name: mid-server
        image: servicenow/mid-server:latest
        env:
        - name: YOUR_INSTANCE_URL
          value: "https://dev395227.service-now.com"
        - name: MID_INSTANCE_USERNAME
          value: "admin"
        - name: MID_INSTANCE_PASSWORD
          valueFrom:
            secretKeyRef:
              name: servicenow-mid-creds
              key: SN_PASSWD
        - name: MID_SERVER_NAME
          value: "K8s_Homelab_MID_Server"
