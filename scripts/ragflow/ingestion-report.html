Legenda delle metriche

Due orologi: task è il lavoro vero letto da Task done (Xs) nel log; wall è process_duration, che include coda Redis, retry e Ollama giù.

docs / done / fail

Quanti file nel dataset, quanti finiti, quanti in errore. other sarebbe RUNNING/CANCEL; qui è 0.

p50 (mediana)

Metà dei documenti è più veloce, metà più lenta. È il tempo del file tipico, non distorto dai pochi PDF lunghi.

p95 (coda)

Il 95% è più veloce di questo valore; solo 1 file su 20 è peggio. Serve per dimensionare, non per descrivere il caso comune.

avg e max

La media sale se hai outlier (es. manuali ASUS). Il max è il singolo peggiore. Se avg > p50, la distribuzione ha una coda lunga.

task_sum

Somma dei tempi di lavoro. Con DOC_BULK_SIZE=4 il wall del batch è circa task_sum / 4, non la somma seriale.

wall p50 / p95

Quanto il job è rimasto aperto. Su OPNsense wall ≫ task perché 421 file aspettano in coda. Non è costo DeepDoc.

OCR / layout / tabelle

Fasi DeepDoc sui PDF. Assenti sui markdown (trattino). In k8s-lab le tabelle dominano.

embedding / indexing

Embedding = bge-m3 su Ollama. Indexing = scrittura su Infinity. Sui markdown l’indexing è il pezzo più lento.
